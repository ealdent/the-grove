Neural cellular automata · WebGL2 workbench

Sixteen channels, one shader pass.

Every cell on this grid carries sixteen numbers and runs the same small neural network. Each step it reads its 3 × 3 neighborhood through four filters, sends the 64 results through two dense layers, and adds the answer to its own state; the GPU writes all sixteen channels in a single pass. Paint emitters, voids and anchors into the running medium, or scramble its hidden state and see what each rule makes of the wreckage.

How it works

One update, start to finish

  1. 3 × 3neighborhood, sixteen channels per cell
  2. × 4filters: identity, Sobel x, Sobel y, Laplacian
  3. 64perception inputs per cell
  4. 64hidden units, ReLU
  5. 16deltas, with c0–c2 held at zero
  6. s + Δadded to the state, clamped to ±4

Sixteen channels in four textures

The state lives in four RGBA16F textures of four channels each. One fragment-shader pass reads all four and writes four render targets at once (WebGL2’s multiple render targets), so every channel updates together. Two copies take turns: one is read while the other is written.

c0–c2 are the inputs you paint. The network reads them but can never change them. c3 is the readout, shown as σ(2·c3), and c4–c15 are hidden working memory.

What a cell sees

Every channel passes through four 3 × 3 filters: identity, Sobel x and Sobel y (scaled by ⅛) and a Laplacian (scaled by 1/16). The grid wraps at its edges, so every cell has eight neighbors. Sixteen channels times four filters gives 64 numbers per cell: the perception step of Growing Neural Cellular Automata with a Laplacian added.

A network in every cell

A dense layer maps the 64 inputs to 64 ReLU units, and a second maps those to 16 deltas: 5,120 multiply-adds per cell per step. The shader computes four hidden units at a time and folds each group straight into the output, so the hidden layer is never stored. A random gate updates each cell with probability p, so cells don’t move in lockstep.

Weights in a 64 × 21 texture

All 5,376 parameters sit in one RGBA32F texture. Rows 0–15 hold W1 (a row per four hidden units, a column per input), rows 16–19 hold W2 (a row per four output channels, a column per hidden unit), and row 20 holds the biases: b1 in columns 0–15, b2 in 16–19. Inputs run filter by filter: 0–15 identity, 16–31 Sobel x, 32–47 Sobel y, 48–63 Laplacian.

A .bin file is that texture as raw little-endian float32, row 0 first and RGBA within each texel.

About the three presets

They are wired by hand, not trained: each is a textbook equation written as one hidden layer. A linear term costs a pair of ReLU units, one passing +x and one passing −x. A threshold costs two more, a steep ramp clipped at 0 and 1. A term that should act only inside a painted sensor gets a pair whose bias keeps it switched off wherever that sensor is 0. Pacemaker waves and Spiral turbulence are the same excitable medium (a piecewise-linear FitzHugh–Nagumo model) with different recovery rates; the ripple tank is the damped wave equation, driven by a clock that every cell keeps. Hover the weight map to trace any term. To try trained weights, export a .bin to see the layout, then load your own.

Background: Growing Neural Cellular Automata (Mordvintsev, Randazzo, Niklasson and Levin, Distill, 2020) introduced the Sobel perception, residual update and random per-cell updates used here. Everything runs on your GPU; nothing is uploaded.
