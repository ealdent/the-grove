What the machine is

In 1936 Alan Turing described the simplest machine that can carry out any calculation a person can do by following rules. It has a tape divided into squares, each holding one symbol. It has a head that looks at one square at a time, can replace its symbol, and can move one square left or right. It has a controller that is always in one of finitely many states. And it has a table: for every state and every symbol, what to write, which way to move and which state to enter next.

Nothing else is remembered. Anything bigger than a state has to be written on the tape, and that restriction is the point: if a machine this plain can do something, it can be done by following rules mechanically.

The machine above is built exactly that way. When you pick a board size the page compiles the controller into a table, 902 states by 13 symbols, and from then on every step is a single lookup in it. Turing named his states with Fraktur letters, and so does this controller: scan s, go g, read r, home h, print p, back b and commit c.

A plane laid on a line

Life happens on a grid, but the tape is a single line, so the board is written out row by row, the way you read a page. Every row is wrapped in an X at each end, a row of X squares runs above and below the board, and # closes every row. The X squares are cells that are always dead, so the edge of the board needs no rules of its own.

Because every row takes n + 3 squares, the neighbour directly above any cell is always n + 3 squares to its left, and the diagonal neighbours are one square to either side of that. The distances are the same for every cell, and that is what lets a finite controller count them.

Conway is said to have worked Life out by hand over lunches on a Go board, so the boards here are Go boards: black stones for the generation on the tape now, white stones for the one being written. The light is the head.

Eight errands for every cell

  1. Scan moves right until it finds a square that still holds a plain 0 or 1, and marks it: 0 becomes 0*, 1 becomes 1*. The state now remembers the cell’s old value.
  2. Go walks to the next neighbour, counting the squares down in its state.
  3. Read adds the neighbour’s old value to the live count the state carries. An X adds nothing.
  4. Home walks back until it sees the mark. Go, Read and Home repeat for all eight neighbours, from north-west to south-east.
  5. Print replaces the mark with a pair, the old value and the new one side by side in one square.

The new value follows Conway’s rule: a cell is alive in the next generation if it has exactly three live neighbours, or if it is alive now and has exactly two.

Writing a pair instead of just the new value is what keeps the update simultaneous, as Life requires. The cells further right still need this cell’s old value when they count their own neighbours, so it stays on the tape, in the first half of the pair, until every cell has been decided. Textbooks call this a two-track tape: each square still holds one symbol, but the symbol carries two values. The tape above draws the tracks one above the other, with the new value on a white stone.

Committing a generation

When Scan reaches ⟩, every cell holds a pair. Back rewinds to ⟨, Commit sweeps right replacing each pair with its new half, so 01 becomes 1, and Back rewinds once more to start the next generation. Watch the boards during the sweep: the white stones pour into the left-hand board as the head passes.

How big the controller is

The state has to carry everything the machine is in the middle of: which of the eight neighbours it is visiting, how many squares are left to walk, how many live neighbours it has counted, and the cell’s old value. Counting every state the controller can reach gives 54n + 362 states for an n × n board.

Only the walking distance grows with the board, so strictly this page holds a family of machines, one for each size. A single machine for every size would have to measure its walks on the tape instead of counting them in its state, with extra marks and many more steps. The stay moves, S in the table, are a convenience: each could be replaced by one step right and one step back.

Why it is slow

Each cell costs 58 + 12n steps, and almost all of them are walking: the three neighbours above and the three below are a whole row away, and the head goes there and back for each. A full generation takes 12n3 + 61n2 + 20n + 29 steps; the first is a little shorter because the machine starts at the left end instead of rewinding to it. Doubling the side of the board multiplies the work by about eight.

A glider moves one cell every four generations. On a 14 × 14 board each of its diagonal steps costs 180,772 tape steps.

A glider at full speed

Life can run a Turing machine, too

The relationship runs both ways. Berlekamp, Conway and Guy showed in 1982 that Life can compute anything a Turing machine can, using streams of gliders as signals, and in 2000 Paul Rendell built a working Turing machine out of Life patterns. A Turing machine can run Life, and Life can run a Turing machine, slowly in both directions.
