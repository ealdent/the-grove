A signature in the odds.

01 · Before the watermark

A model chooses one token at a time.

Given the text so far, a language model assigns every possible next token a probability. A token might be a word, part of a word, punctuation, or whitespace.

Temperature reshapes the same menu. Lower temperatures concentrate probability on the favorite; higher temperatures spread it among alternatives. A watermark needs alternatives: if one token has nearly all the probability, there is little room to carry a signal.

02 · The secret pattern

The key changes what “favored” means.

For the recent token context and a private key, SynthID derives pseudorandom g-values for each possible token and each tournament layer. In the paper’s main setting, every g-value is either 0 or 1.

There is no permanent green vocabulary. Change the sentence or the key and the pattern changes. That context dependence makes the signal hard to infer from one short passage.

The published experiments use a four-token context window and mostly Bernoulli(0.5) g-values. See the Nature paper and supplement.

03 · Watermarked sampling

Sample candidates. Let the g-values choose.

The conceptual algorithm samples 2m candidates from the model’s original next-token probabilities, then runs an m-layer tournament. In each pair, the candidate with the larger keyed g-value advances; equal g-values use a random tie-break.

This is not choosing from the whole vocabulary. It is choosing among candidates already sampled from the model—and duplicate candidates are allowed.

Toy versus production: this lab uses three layers and eight visible candidates. The paper often evaluates 30 layers. An equivalent vectorized update avoids literally sampling 230 candidates.

04 · The subtle guarantee

“Non-distortionary” is an average, not a freeze.

With two competitors, the paper proves that averaging one token’s sampler over a uniformly random seed r recovers the model’s original token distribution. The sequence-level theorem instead averages over the randomized key k and assumes full repeated-context handling. One fixed seed or key can still shift a particular step.

It does not mean a watermarked response equals an unwatermarked response, or that every fixed key leaves every probability untouched.

Er[ Pr(S(p, r) = x) ] = p(x)

This statement depends on the paper’s assumptions, including repeated-context handling for sequence-level guarantees. Public implementations bound their stored context history. See Methods: non-distortionary watermarking.

05 · Reconstructing the signal

The detector repeats the secret calculation.

Given the exact tokenizer, key, context rule, and watermark configuration, a detector rebuilds each token’s g-values. It sums the evidence across unmasked positions and tournament layers.

When a context repeats, the published generator bypasses the tournament and samples from the base model; the detector masks that same position. Reusing the secret pattern would violate the independence assumed by simple null calculations. The first incomplete context and special tokens may also be excluded in real implementations.

Smean = [1 / (m|T̂|)] Σt∈T̂ Σℓ=1…m gt,ℓ

The paper describes mean, weighted, frequentist, and learned Bayesian scorers. This page uses the transparent mean score only. See the official reference implementation.

06 · Why length and entropy matter

A pattern becomes visible across many choices.

Under this toy null model, g-values average near 0.5. Matching-key watermarked samples tend higher. Longer passages tighten both score distributions, making separation easier.

High-entropy contexts offer genuine alternatives. When a model is nearly certain of the next token, the tournament repeatedly sees the same candidate and cannot add much signal.

Cp = Σxp(x)2   ·   Prwm[g = 1] = 0.5 + 0.25(1 − Cp)

For one binary two-candidate layer, that equation makes the entropy effect exact: a one-hot distribution has Cp = 1 and adds no expected signal.

Read the chart as repeated experiments. A single score is not a probability that text is AI-written. It is evidence under one known watermark configuration and one calibrated null.

07 · From score to decision

A threshold chooses the errors you tolerate.

Raise the positive threshold and false alarms usually fall, but more watermarked text is missed. Lower it and sensitivity rises along with false positives. Production thresholds must be calibrated for text length, domain, detector, and operating base rate.

A selective detector can set a lower negative boundary too, then abstain between the two instead of forcing an answer.

Base rates still matter. If only 1% of tested passages are actually marked, even 95% sensitivity at a 1% false-positive rate yields roughly 49% positive predictive value. That is arithmetic from an illustrative prevalence—not a headline paper result.

The paper reports true-positive rate at an empirically calibrated 1% false-positive rate—not a universal accuracy score—and evaluates length-specific selective prediction. See Evaluation of SynthID-Text.

08 · Edits and attacks

The signal can bend. It can also break.

Deleting, replacing, translating, or paraphrasing tokens changes both token evidence and downstream context seeds. Some local edits leave enough untouched material to detect; thorough rewriting can sharply reduce confidence.

Generating directly in the eight languages tested by the paper is different from translating an already-watermarked passage: the former performed well in those experiments, while translation can destroy much of the original token-level evidence.

Robustness is empirical, not absolute. The paper tested random word deletion and sentence-by-sentence paraphrasing on a specific benchmark. It does not prove immunity to all editors or attacks.

The robustness experiment used 3,000 ELI5 samples, 20% or 50% random word deletion, and Gemini Ultra paraphrases. See Supplementary §C.6 and Fig. C3.

09 · A family of approaches

SynthID is one design point, not “the AI detector.”

Text provenance methods trade off generator access, quality change, sampling diversity, robustness, and what a positive result can mean. These families are related but not interchangeable.

10 · What the paper does—and does not—establish

A keyed watermark answers a narrow question well.

With the right secret setup, it can provide statistical evidence that text passed through that specific watermarking sampler. It cannot establish who wrote a passage, whether every sentence is factual, or whether unknown text came from “AI” in general.

01 / Configuration

No key, no verification.

The detector needs the matching tokenizer, hash or sampling table, context policy, layer configuration, key, and compatible calibrated scorer.

02 / Attribution

Evidence is not authorship.

A positive result supports one watermark hypothesis. A negative result may mean no mark, too little text, low entropy, edits, or the wrong configuration.

03 / Adversaries

Rewriting can remove signal.

Cropping and mild edits may preserve evidence; extensive paraphrase, translation, or regeneration can substantially reduce it.

04 / Public code

The demo is not Gemini’s detector.

The public Hugging Face processor explicitly uses a different hash from Gemini. Detectors trained on that public configuration do not transfer to Gemini text.

05 / Quality study

Strong evidence, scoped claim.

About 20 million live Gemini responses showed no statistically significant change in thumbs feedback; a 3,000-prompt human study likewise found no significant preference difference.

06 / Performance

One measured overhead.

The reported 30-layer Gemma 7B-IT setup took 15.615 versus 15.527 ms per token—0.57% on four TPU v5e chips. That is not a universal hardware benchmark.

Technical drawer: deployment details worth knowing

The public reference code is a research aid, not Google’s production system. Its hash is not presented as cryptographically secure. The Hugging Face Bayesian detector must be trained for each unique key/configuration on representative, independent positive and negative examples. Hardware-dependent deterministic randomness can matter. Repeated-context history is bounded in public APIs even though the cleanest mathematical sequence guarantee assumes full retained history.

The paper also studies distortionary tournaments with more than two competitors, learned layer weights, speculative decoding, multilingual generation, watermark stealing and spoofing, and block-max scoring for mixed passages. Watermarked responses to the same prompt can become more similar under one fixed key, creating a diversity and watermark-stealing risk. Testing many keys or windows also inflates false-positive risk unless calibration accounts for those multiple tests.

Quality, latency, detector, and limitation claims in this section come from the open Nature article, its supplement, the DeepMind reference repository, and pinned Hugging Face source.
