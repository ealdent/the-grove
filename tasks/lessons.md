- Volumetric light (godray cones, light shafts, fog volumes) must ABSORB as well as emit. `AdditiveBlending` can only brighten, so the background keeps its full contrast and shows straight through the beam as a ghostly negative image. Real media is `bg * T + L`; setting `L = colour * (1 - T)` makes that ordinary alpha-over, so use `NormalBlending` with alpha as *density* and a colour whose components exceed 1 so the dense core tone-maps to a glow instead of flat paint. Bonus: when every fragment emits the same colour, alpha-over is order-independent (`c·(a₁+a₂−a₁a₂)` either way), so a single InstancedMesh of overlapping cones needs no depth sorting.
- Additive volumetrics also need a *near-camera* fade (`smoothstep(1.0, 4.5, length(viewPos))`). The shaft you are standing inside fills the screen and paints everything behind it; fading it out within a few metres is both what real godrays look like and the single biggest fix for "it's washing out the whole scene". Prove which layer causes a wash by pinning its intensity uniform to 0 and re-shooting — don't guess between the light and the haze.
- Soft edges on a volumetric cone come from `alpha *= pow(abs(dot(normal, viewDir)), k)` — peak down the axis where a sightline crosses the most air, zero at the silhouette. It removes the hard geometric outline and approximates real path length. Keep the fade ramp at the emitter end SHORT, or the glow bleeds over the fixture and the lampshade loses its edge.

- `makeFbmField(size, octaves, baseFreq)` requires an **integer** `baseFreq`. NaN then lands in a `Uint8ClampedArray` as 0 — so the failure is silent and spectacular: a black albedo *and* a roughness map of zero, i.e. mirror-finish surfaces reflecting the sky as flat blue sheets, with nothing in the console. - Painted texture features have to be sized in **world units, not texels**. - Volumetric alpha and volumetric radiance are separate dials, and re-tuning the room's ambient invalidates both. - A fog *sheet* needs the inverse of a light cone's facing term: `pow(1 - |dot(n, viewDir)|, k)`. A horizontal plane seen face-on is millimetres of air and must contribute nothing; seen along its length it is metres. Without it the layer nearest the camera lands on the floor as a flat white smear. - In three.js, `shadow.autoUpdate = false` + `shadow.needsUpdate = true` on demand is the single biggest win available in a static scene. - Headless Chrome under `--virtual-time-budget` hands `requestAnimationFrame` a delta of ~0, so anything integrated over real time (a filament warm-up, a flicker, a sway) freezes after one frame and cannot be observed at all. - Parametrising anything around a rounded rectangle (a border shader, a path, a marching light) must use the **ray angle from the centre**, not a projection to the nearest edge. Nearest-edge is discontinuous along every corner diagonal — approaching the top-right corner diagonally, the "top edge" branch and the "right edge" branch disagree by twice the inset distance — so every strand kinks inside every corner. - JavaScript String.replace() treats `$$` in the REPLACEMENT string as an escape for one literal `$` — a codemod that writes code containing `$$` (a jQuery-style helper, shell strings) silently emits `$`, and the two identically-named helpers then shadow each other with errors that point far from the cause. Use a replacer function (`() => newText`) for any replacement string containing `$`, and grep the output for the expected identifier after every codemod.
- CSS `aspect-ratio` TRANSFERS min/max constraints through the ratio: `aspect-ratio: 16/8; min-height: 240px` implies min-WIDTH 480px, which silently overflows a 375px phone even though nothing on the page declares a width. For responsive stages, drop the min-height and switch the aspect-ratio in a media query instead. Related: text drawn onto such a canvas should be sized by measureText-and-shrink against the longest line, not by height-only ratios.
- An absolutely positioned `<canvas>` is a replaced element: `inset` alone positions it but does NOT stretch it — the used width/height fall back to the drawing-buffer attributes, so a canvas that JS sizes at `rect * dpr` displays at dpr-times the intended CSS size. At dpr 1 (headless default) it looks perfect; on the user's retina screen the border ring rendered around four tiles instead of one. State the box outright (`width: calc(100% + 2*overflow)`) or set `canvas.style.width/height` in JS — the repo's own vines demo documents this exact quirk, and the typewriter page did it right the same day the index badge got it wrong. When verifying overlay geometry, screenshot at `--force-device-scale-factor=2` as well as dpr 1.

- When a large `Edit` `old_string` fails to match a file you "just read", do not retype it from memory of the read output — transcription drift is the bug (I mistyped `Math.sin(eclLat)` as `Math.cos(eclLat)` twice while deleting a dead code block). Write the candidate to a temp file, byte-diff it against the file region (`while (cand[i]===region[i]) i++`), and fix the exact offset the diff names. For single-file rewrites of a whole region, a small scripted splice with assertions is cheaper than three failed 80-line edits.
- Browserify UMD bundles (e.g. astronomy-engine `astronomy.browser.min.js`) attach differently by module context: `require()` of a `.js` file under a `"type":"module"` package sets the global (`global.Astronomy`) and returns `{}`, but under `.cjs` the UMD takes the CommonJS branch and assigns `module.exports` — the global is never set, so a page script that expects the global silently degrades. In harnesses, do `const A = require(p); if (!global.Astronomy) global.Astronomy = A;`. `SearchHourAngle` returns `{time: AstroTime, hor}` (use `.time.date`); `SearchRiseSet`/`SearchAltitude` return events with `.date` directly.
- Verifying a timezone-dependent page headlessly works without a browser: stub `Date` (subclass with fixed `now`, `Date.prototype = RealDate.prototype` keeps `instanceof` alive), a registry-backed `document.getElementById`, `navigator`, `fetch`, and `setInterval`; then `eval` the extracted inline `<script>` IIFE and assert on what the stub elements received. Set `process.env.TZ` per scenario before eval so `Intl` day-boundary logic sees the target zone.

- If a demo's premise is "a normal web UI element with a shader effect," build the element in REAL DOM and make the shader a transparent overlay — do not paint the element inside the fragment shader. The blood-splat demo drew its whole form (card, inputs, and a capsule-glyph "SUBMIT" label) in GLSL, and no amount of glyph tuning could make it read as a real button; Jason's verdict was "regular font, literally like a submit button on a normal website, not that weird one." The overlay pattern also anchors effect coordinates to the live element (`getBoundingClientRect` per frame), so the effect tracks reflow, keyboard activation, and theming for free, and shrinks the shader to just the effect. Express procedural-effect geometry in units of one pattern radius (`nb = q / uR0`) sized off the element so the pattern is scale-invariant.
- The Browser pane pumps rAF only on `computer` screenshot actions (not `javascript_exec`), ~2-3 frames (~0.1s of clamped dt) per shot; headless Chrome's `--virtual-time-budget` starves rAF in both `--dump-dom` and `--screenshot` modes (a 12s budget advanced the loop <0.7s). To verify time-threshold logic in an rAF loop (auto-triggers, "finish at t>=X"), shrink the threshold via an exposed live-params object (`__demo.P.autoDelay = 0.2`) and pump batches of scale-0.1 screenshots, polling exposed state between batches. For anything visual, pinned-uniform query params (`?pin=<age>`) stay the reliable route.
- A headless-Chrome canvas game driven by a setInterval test clock renders blank in --screenshot mode even though getImageData probes inside the page show full content: without a live rAF the compositor never presents the canvas, so the capture shows only the body background.
